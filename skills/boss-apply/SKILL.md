# Boss 投递

## 开始

读根目录规则、`templates/求职标准.md`、`templates/面试口径.md` 和已有 `投递记录.md`。确认本轮城市、岗位方向、学历/届次、数量及发送授权；未授权时只读筛选。工具前缀以客户端实际显示为准，所有 Boss 页面操作均使用本仓库 MCP。

`connection_status` → 确认扩展连接和控制权 → `read_current_page` 核对账号、页面。先少量只读验证筛选准确，之后按用户已授权范围连续执行。

## 搜索与筛选

1. `search_jobs(query, city)` → `read_jobs`。过滤按本人的真实条件，不套用仓库作者的职业、薪资或城市。
2. 找到候选后 `open_job(keyword)` → `read_job_detail` 阅读完整 JD。公司名、岗位标题、工作内容、地点、经验、学历和待遇分别核对；校招还核毕业年份。
3. 按岗位主体职责判断，次要技能缺口和硬门槛分开。作息或合同主体不清楚则标待问，不把推测当事实。
4. 需要更多结果时 `scroll_jobs`，用新职位 ID 和实际卡片核对增量；没有新增就换有效查询，避免无限翻页。`read_jobs` 的 `max` 是返回条数，不证明网站只有这些岗位。
5. 通用工具不够时 `debug_dom` 查看真实结构，再使用 MCP 的 `dom_click` / `dom_fill`。发送动作结果不明时先回读，不换自动化通道继续试。

## 每家投递

1. 查记录避免重复，完整读取 JD 并通过本人的条件。
2. `greet` 建立沟通。页面可能发送默认招呼、弹出页内聊天或跳到聊天页，先读实际结果；按钮已为“继续沟通”时不重复建聊。
3. `read_current_page` 核对当前公司、HR、完整职位。工具返回的职位标题与当前页面不符时，以实际详情核验并停用旧缓存。
4. 按 JD 写一两句真实匹配点；需要补充时 `fill_reply` → 核对输入和目标 → `send_reply`。每家单独执行。
5. 回读聊天记录，只有看见刚才内容才记录发送成功。跳转、超时、按钮点击成功均不等于送达。
6. 记录职位 ID/链接、匹配理由、实际动作与状态。用户授权的数量到达即停，不为了凑数放宽条件。

## 回复与收工

收到 HR 新消息时先按 `../boss-reply/SKILL.md` 处理，再回到投递。完成后核对记录，汇报成功投递数、未核实/失败数、回复与面试进展，调用 `release_control`。

账号异常、验证码或平台限制出现时立即停止当前自动任务，保留提示及调用记录，由本人按平台流程处理。
