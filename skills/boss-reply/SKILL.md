# Boss 代聊

## 读取与定位

先读根目录规则和两份个人资料，`connection_status` 核对扩展与控制权，再 `read_conversations` 找待回复对话。按公司/HR关键词定位，列表 index 会变。

`open_conversation(keyword)` → `read_current_page`，核对公司、HR、完整职位和最近双方消息。已婉拒、收尾或本人已回复的对话不重复跟进。职位缓存与页面标题不符时，先读实际职位详情，确认后再措辞。

## 回什么

- 不匹配：按本人条件简短说明方向，只有已授权代聊时才发送。
- 对口：结合 JD 和真实项目表达兴趣；职位已写明的信息不重复询问。
- 事实问题：按 `templates/面试口径.md`；资料没有的事实列待补，不猜。
- 附件：确认本人最新附件文件名；`chat_action(action="send_resume")` 先看可选清单，再带明确 `resume` 关键词发送。动作可能受双方互动门槛限制，回读确认。
- 微信/电话：只有用户授权才执行 `chat_action` 对应交换；核对交换的是当前求职者资料，不把 HR 联系方式填成本人信息。
- 面试：先收集日期、时间、方式、地址、岗位；按本人可用时段协商，最终确认按用户授权执行。实际确认后记录日程，未确认写待定。

## 发与核验

1. 每次外发前重读目标公司、HR、职位和当前输入。用户本人正在操作时避免交错；发现不属于本次的草稿先保留。
2. `fill_reply` 填好后，再调用 `send_reply`。工具优先点可见发送按钮，回传 `attempted` 不代表送达。
3. `read_current_page` 检查最新聊天中出现原文。默认招呼、附件请求或交换卡片已经出现时，不重复发送。
4. 只有确认聊天中未出现内容、输入框仍为本次原文、页面无异常、对话目标未变时，才可重新填一次并再发送一次，然后回读。仍失败就记录具体结果，停止这一动作；超时且结果未知时不盲重发。
5. 特殊弹层先 `debug_dom` 看可见元素，排除隐藏/离场节点，再用 MCP 的 `dom_click`。任意点击同样按外发授权和限速执行。

## 收工

在 `投递记录.md` 记录回复、附件、面试和待补事实的真实状态。完成后 `release_control`。监听只在宿主确实支持后台通知时按 `docs/架构与原理.md` 注册，不能把一个普通 shell 后台进程说成持续在线代聊。

出现账号异常、验证码或平台限制即停止自动操作，保留原提示，由本人处理。
